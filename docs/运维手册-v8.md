# 运维手册 · v8 T3 自动化流水线

> 适用版本：Stage 4（2026-11-11）—— Launch Library 2.2 自动同步（B1 流水线）**自动上线版**
> 配套文档：`docs/数据字典.md`（字段 / 校验规则）、`docs/pending-china.md`（中国事件人工待审）
> 运行环境：Node 18+（脚本零第三方依赖，用内置 `fetch` / `vm`）
>
> **v8.1 变更**：流水线由「只开 PR、人工 merge」改为「硬门禁后自动提交并推送 `master`」，Pages 随 `master` 自动重新发布。详见 §10。

---

## 1. 流水线总览（B1）

```
┌──────────────┐   ┌──────────────┐   ┌────────────────┐   ┌──────────────────┐
│fetch-launches│ → │ merge-data   │ → │validate-data   │ → │ commit + push    │
│  (抓取+缓存)  │   │ (映射+合并)   │   │ (硬门禁)        │   │ master → Pages   │
└──────────────┘   └──────────────┘   └────────────────┘   └──────────────────┘
   LL API 匿名/令牌      不动中国事件        任一 FAIL→exit 1      无 diff 则跳过
   限额≤6 请求/次       写盘前自检           → 绝不推送            → 自动重新发布
```

- **定时**：GitHub Actions 每日 UTC 02:23 / 14:23（北京时间 10:23 / 22:23），避开整点拥堵。
- **手动**：仓库 **Actions → sync-data → Run workflow**，可勾选 `backfill`（宽窗口首次回填 llId）或 `force_update`（首次也更新事实字段）。
- **结果**：`data.js` / `docs/pending-china.md` 有 diff 且 `validate-data.js` ALL PASS 时，**自动提交并推送 `master`**，无需人工介入；无变更则 `master` 保持不动。每次同步是独立 commit，可单独 revert。
- **Pages 发布（关键）**：GitHub 官方限制「`GITHUB_TOKEN` 推送的提交不会触发 legacy Pages 构建」。因此推送成功后，流水线会用 `pages: write` 权限**显式调用 `POST /repos/{owner}/{repo}/pages/builds`** 请求一次构建（实测返回 201 queued），效果等同往默认分支推一次提交，但不需要额外 commit。这一步是"同步即上线"闭环的最后一环，不可删。
- **运行摘要**：写入 Actions 运行页的 **Step Summary**（`.sync/summary.md` 已 gitignore，不入库），含逐字段 diff、拦截项、中国待审清单。

## 2. 各组件职责

| 文件 | 职责 |
|------|------|
| `scripts/fetch-launches.js` | 从 LL 2.2 抓 `previous`(已发射) / `upcoming`(计划)，落盘 `.sync/raw-*.json` 缓存。限额保护（≤6 请求/次）、网络失败降级为空结果（exit 0 不阻塞）。自动检测 `data.js` 无真实 `llId` 时启用宽窗口回填。 |
| `scripts/merge-data.js` | 把抓取结果映射为本站事件字段，按 `llId` / (日期+型号) 匹配存量事件，逐字段合并。支持 `--dry-run`（只报告不写盘）、`--force-update`。 |
| `scripts/glossary.js` | 映射词典：火箭型号、发射场、运营方、状态、类型、是否中国、星数解析、北京时转换。被上述两脚本与校验器共用。 |
| `scripts/validate-data.js` | 数据门禁（R0–R15）。任一 FAIL → exit 1，CI 不会推送。R13 为 **warning 级（不阻塞）**。 |
| `.github/workflows/sync-data.yml` | CI 编排：checkout → setup-node → fetch → merge → validate(门禁) → Step Summary → commit/push `master` → 显式请求 Pages 构建。 |

## 3. 安全机制（"宁可漏抓不可污染"）

1. **中国事件永不入库** —— 命中即分流到 `docs/pending-china.md`，`EVENTS` 一行不动。该文件会被自动提交，便于人工一眼看到待办。
2. **全局保护字段永不覆盖** —— `name/pl/op/opKey/cat/ty/hl/note/tbd/month/lock/llId` 等由人工维护。
3. **逐事件 `lock` 数组** —— 可锁住"事实字段也信人工"的场景（如垣信批次星数先于 API 公布，见 `m7-3` 的 `lock:["satCount","st"]`）。
4. **写盘前自检** —— 语法可编译 + 事件数不丢失 + 保护字段零漂移 + id 不重复；任一不满足**拒绝写盘**。
5. **未来日期铁律** —— `net` 晚于今天 = 发射尚未发生，禁止写入 `st`/`satCount` 等结果字段；`previous` 端点出现未来事件一律进待审不入库。
6. **校验硬门禁前置** —— `validate-data.js` 在提交之前运行，FAIL 即终止 job，`master` 不受影响。
7. **冲突安全放弃** —— 与人工推送撞车时 rebase 重试最多 3 次；仍冲突则打印 warning 并放弃本次同步，**绝不 force push**，下次定时自动重试。

## 5. 日常运维 SOP

### 5.1 查看同步结果
进入仓库 **Actions → sync-data → 最近一次运行 → Summary**。摘要已列出：新增事件、字段变更明细、未来日期拦截、被 `lock` 跳过项、待补星数、中国待审、未匹配项。也可直接看 `master` 的 commit 历史。

### 5.2 处理 `docs/pending-china.md`（中国事件）
LL 对中国任务覆盖不全，故只列建议字段值、**不自动入库**。
1. 逐条核实（对照官方通报 / 新闻）。
2. 确认无误 → 按建议字段手工写入 `data.js` 的 `EVENTS`（含 `llId` 以便后续去重）。
3. 删除该条目；清单保持为空即表示无积压。

### 5.3 处理 R13 过期计划（warning 级，不阻塞但需清理）
`st:"plan"` 且窗口末日 `e < DATA_ASOF` 的事件。DATA_ASOF 推进后会出现。流水线无权自动回填中国事件，故需人工：
- 已发射 → 改 `st:"done"` 并补 `satCount`/`src`；
- 失败 → `st:"fail"`；
- 推迟 → `st:"delay"`（参照 `qf30→delay` 先例）。
改完重跑 `workflow_dispatch` 即可。

### 5.4 处理"待人工补星数"（needSatCount）
`st:"done"` 但 `satCount:0` 的事件，疑漏抓星数。仍会自动提交，需在后续人工补齐 `satCount`。

### 5.5 处理未匹配（unmatched）
- **歧义**：同一 (日期+型号) 命中多条候选 → 人工判断归口。
- **型号未收录**：LL 火箭名不在 `glossary.js` → 补词典或人工写 `EVENTS`。
- **计划事件不新增**：`upcoming` 端点只用于更新已有 `plan` 事件日期，不自动建新事件。

## 6. 首次 llId 回填（backfill）

`data.js` 尚无真实 `llId` 字段时，`fetch-launches.js` 自动启用 400 天宽窗口，`merge-data.js` 进入"仅回填 llId"模式（首轮内容零误改）。回填随流水线**自动推送 `master`**，之后常规运行按主键精准匹配。

> 判定正则只匹配真实赋值 `llId:"..."`；`data.js` 顶部字段说明注释里的 `llId: [可选]` 不会被误判（v8.1 修复了此前导致回填永不启用的 bug）。

- **CI**：Actions → sync-data → Run workflow → 勾选 `backfill`（可选，自动检测已覆盖）。
- **本地**：
  ```bash
  node scripts/fetch-launches.js --backfill
  node scripts/merge-data.js            # 首次自动仅回填 llId
  node scripts/validate-data.js         # 必须 ALL PASS
  ```

## 7. 本地联调（不联网、不污染）

```bash
# 只读缓存，绝不发请求
node scripts/fetch-launches.js --offline
# 只报告不写盘，可反复验证映射/合并逻辑
node scripts/merge-data.js --dry-run
# 改完数据必须跑，ALL PASS 才能提交
node scripts/validate-data.js
```
> 联调产物落在 `.sync/`（已 gitignore），不会进仓库。建议联调后删除 `.sync/` 以保证下次运行重新抓取。

## 8. 配置

| 项 | 说明 |
|----|------|
| `GITHUB_TOKEN` 权限 | workflow 内声明 `contents: write`（推送）+ `pages: write`（请求 Pages 构建）；仓库默认 Workflow permissions 为 read，靠 workflow 内显式声明提权。 |
| `LL_API_KEY`（仓库 Secret，可选） | LL 匿名档额度约 15 请求/小时/IP；配置令牌可提额。缺省匿名也能跑。 |
| `LL_LOOKBACK_DAYS` / `LL_UPCOMING_DAYS` | 常规回看 3 天 / 前瞻 30 天（兜住 API 补录延迟）。 |
| `LL_BACKFILL_DAYS` | 回填窗口默认 400 天（覆盖全年度）。 |
| `LL_CACHE_TTL_H` | 缓存新鲜小时数，默认 6。 |
| `LL_TIMEOUT_MS` | 单请求超时，默认 20000。 |

限额硬上限 `MAX_REQUESTS=6`（previous 最多 3 页 + upcoming 最多 2 页 + 1 余量）。
仓库 **Settings → Actions → Workflow permissions** 需允许读写；workflow 内已显式声明 `permissions: contents: write`。`master` 无分支保护、无 rulesets。

## 9. 故障排查

| 现象 | 原因 / 处理 |
|------|------|
| `master` 没前进 | 本次无变更（合并报告"无任何变更"）或 validate FAIL。看 Actions 日志与 Step Summary。 |
| 日志出现"与人工提交冲突" | 推送瞬间有人工作业；本次安全放弃，下次定时自动重试。无需干预。 |
| validate 报 R14 | 两条事件占用同一 `llId` → 删误加的那个（`llId` 由流水线回填，人工不填）。 |
| validate 报 R15 | `lock` 含非法字段 → 只锁 `{s,e,t,st,satCount,src}`。 |
| R13 持续 WARN | 有 `plan` 且窗口已过事件 → 按 §5.3 人工回填。 |
| 抓取 0 条 / 降级 | 网络失败或被限流 → 脚本降级为空结果，不阻塞；稍后重跑或配 `LL_API_KEY`。 |
| 新增事件全是未来日期 | `previous` 端点异常返回未来数据 → 已被"未来日期铁律"拦截进待审，需排查抓取窗口。 |
| 推送报 403 | 仓库 Workflow permissions 被改为只读 → 改回 Read and write。 |
| 数据进了 master 但网站没更新 | Pages 构建请求失败（日志有 warning）→ 到 Actions → `pages-build-deployment` 手动重跑，或重新 POST `/pages/builds`。 |

## 10. 回滚与变更

- **发现误改**：`git revert <commit-sha>` 回滚单次自动同步；因每次同步是独立 commit，不影响此前内容。
- **紧急止血**：仓库 **Settings → Actions** 禁用 `sync-data` 工作流，自动同步立即停止；`master` 保持现状。
- **改脚本/工作流**：走普通 PR 合入 `master`。CI 改动生效后，下一次定时/手动运行即采用新版。
- **v8 → v8.1 变更清单**：
  | 项 | v8 | v8.1 |
  |----|----|------|
  | 终点 | `create-pull-request` 开 PR | `git commit` + `push master` |
  | 人工环节 | 必须 review/merge | 无（全自动） |
  | 摘要载体 | PR 正文 | Actions Step Summary |
  | 权限 | `contents: write` + `pull-requests: write` | `contents: write` + `pages: write` |
  | 陈旧产物 | `data/sync` 分支 + PR #1 | 已关闭 / 删除 |
  | 首次回填 | 因正则 bug 从未自动启用 | 修正正则，自动宽窗口回填 |
  | Pages 触发 | merge 后靠人工 commit 触发 | 推送后显式 `POST /pages/builds` |
