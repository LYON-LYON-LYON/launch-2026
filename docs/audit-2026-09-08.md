### 1.3 BUG: 统计栏点击联动是死代码 — P1

**依据**: `index.html` 行 719-731


### 3.2 渲染负载评估

| 元素 | 数量 | 动画 | 说明 |
|------|------|------|------|
| 底层散点星 `.star` | 160 颗 | `twinkle` 4-9s | JS IIFE 生成（行 1443-1455），~16 颗有 `box-shadow` glow |
| 星座簇 `.constellation` | 22 个 SVG | `drift` 160-330s | 12 真实 + 10 程序化，`will-change:transform` |
| 卫星 `.sat` | 1 个 SVG | `satcross` 66s + `blink` 1.6s | 含 `feGaussianBlur` filter |
| 火箭 `.rocket` | 1 个 SVG | `launch` 32s + `flame` .18s | 含 `drop-shadow` filter |
| 流星 `.shooting` | 1 个 div | `shoot` 15s | — |
| **总并发动画** | **~186** | | |

**Intel 核显评估**（Core 5 210H / Intel UHD / 16GB）：
- CSS `transform` 动画走 GPU 合成层，160 颗星的 `twinkle` 仅改 `opacity`+`scale`，开销可控
- 22 个 `drift` 动画用 `translate`+`rotate`，同样是合成层动画
- **潜在瓶颈**: ~16 颗星的 `box-shadow: 0 0 Npx rgba(255,255,255,.7)` glow 效果——`box-shadow` 不是合成层属性，每次 `twinkle` 重绘会触发 shadow 重算。在 Intel UHD 上可能导致轻微帧率下降
- `will-change:transform` 仅声明在 `.constellation`（行 38），160 颗星未声明 `will-change`，可能触发额外的合成层提升开销
- **总体判断**: 可接受，但低端设备可能出现轻微滚动卡顿

### 3.3 z-index 层叠 — PASS

```
.cosmos   → position:fixed; z-index:-1  (深色宇宙背景)
.wrap     → position:relative; z-index:1  (内容层)
.cols7::before → z-index:2  (日历网格线)
.day / .evseg → z-index:1  (日历内容)
```

`.cosmos` 的 `z-index:-1` 配合 `position:fixed`，在 CSS 绘制顺序中位于 body 背景之后、正常内容之前，因此深色宇宙背景**确实可见**，覆盖 body 的 `--bg:#e9eff8` 浅色背景。内容层 `.wrap` 在 `z-index:1`，位于宇宙背景之上。

footer（行 393）和 legend（行 390）使用 `color:rgba(226,234,247,.72)` 浅色文字，适配深色宇宙背景——设计一致。

### 3.4 背景可见性结论

背景层 `z-index:-1` 在浅色 body 背景下**确实可见**（CSS 绘制顺序保证），不会盖住正文（`.wrap` 在 `z-index:1`）。`.cosmos` 设有 `pointer-events:none`，不拦截交互。
